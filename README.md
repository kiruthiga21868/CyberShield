# CyberShield AI

**AI-Powered Cybersecurity Assistant** - a Streamlit application that helps you
evaluate suspicious links, emails, passwords and QR codes before you act on them.

Both machine-learning models are trained offline, committed to the repository,
and run entirely on your own machine. Groq and VirusTotal are **optional**: with
no API keys the application still starts and remains fully usable.

## Features

| Page | What it does | Technique |
| --- | --- | --- |
| **URL Scanner** | Phishing probability, structural indicators, combined risk | Random Forest + rule layer |
| **Email Spam Detector** | Classifies a message and extracts its links | TF-IDF + Multinomial Naive Bayes |
| **Password Analyzer** | 0-100 strength score with an itemised breakdown | Local rule analysis |
| **QR Scanner** | Decodes an image and checks any URL it contains | OpenCV + URL Scanner |
| **Security Score** | Rolls up all four checks into one transparent score | Weighted rules |
| **AI Chatbot** | Answers defensive-security questions | Groq LLM + offline knowledge base |
| **About & Metrics** | Real metrics and limitations from the trained models | `models/metrics.json` |

The application never opens, visits, or follows a URL. It only inspects text.

## Quick start

### Requirements

- Python 3.10 or newer (3.11 recommended for Render)
- No GPU, no database, no external service required

### Install

```bash
git clone <your-repository-url>
cd cybershield-ai

python -m venv .venv
```

Activate it:

```bash
# Windows PowerShell
.\.venv\Scripts\Activate.ps1

# Linux / macOS
source .venv/bin/activate
```

Install dependencies and launch:

```bash
pip install -r requirements.txt
streamlit run app.py
```

The app opens at <http://localhost:8501>.

### Models

Trained artifacts are committed under `models/`, so a fresh clone works
immediately. To rebuild them from the datasets in `data/`:

```bash
python training/train_phishing.py
python training/train_spam.py
```

Both scripts print metrics and write `models/metrics.json` plus confusion
matrix images. Training takes a couple of minutes and needs no GPU.

## Configuration

Everything tunable lives in `config.py`: risk thresholds, rule weights, model
hyper-parameters, file paths and timeout values. No secret is stored in code.

### Optional environment variables

Copy `.env.example` to `.env` and fill in whatever you have:

```bash
cp .env.example .env      # Linux/macOS
Copy-Item .env.example .env   # Windows PowerShell
```

| Variable | Required | Effect when absent |
| --- | --- | --- |
| `GROQ_API_KEY` | No | Chatbot answers from its built-in offline knowledge base |
| `VIRUSTOTAL_API_KEY` | No | URL results use the local model and rule layer only |

Both features **degrade gracefully**. The application never fails to start, and
never shows a stack trace, because a key is missing. Optional tunables include
`GROQ_MODEL`, `GROQ_TEMPERATURE`, `VIRUSTOTAL_TIMEOUT`,
`VIRUSTOTAL_MIN_INTERVAL_SECONDS` and `VIRUSTOTAL_CACHE_TTL_SECONDS`.

> **Do not commit real keys.** `.env` is listed in `.gitignore`.

## How detection works

### URL Scanner - two independent signals, shown side by side

The phishing decision is **not** a bare model assertion. It combines:

1. **The ML probability** from the Random Forest, and
2. **A rule layer** of individually explainable structural checks.

```
rule_score >= 0.55                 -> HIGH
rule_score >= 0.15                 -> MEDIUM
ml_probability >= 0.25             -> MEDIUM   (deliberately capped)
otherwise                          -> LOW
```

The ML signal alone **can never produce HIGH risk**. This cap exists because of
a concrete dataset problem, explained in
[Known limitations](#known-limitations). The UI always displays the model
prediction, the probability, the rule score, the fired indicators and the final
risk separately, so it is always clear which signal drove the verdict.

Rule weights are `HIGH 0.55`, `MEDIUM 0.20`, `INFO 0.03` per hit, summed and
capped at 1.0. Example rules: punycode homographs, `@` in the URL, executable
payload extensions, abused TLDs, non-standard ports, keyword stuffing on a
non-HTTPS host, deeply nested subdomains, and high character entropy.

### Feature extraction

`utils/url_features.py` produces 22 features in a fixed order. Training and
inference call the **same function**, and the trained artifact stores the
feature names. On load the detector compares them against
`ALL_FEATURE_NAMES` and refuses to run on a mismatch, so schema drift cannot
silently corrupt predictions.

### Password Analyzer - privacy by construction

Passwords are analysed locally and are never stored, logged, or transmitted.
The chat page and the VirusTotal service cannot receive a password because
neither is ever given one. Tests assert the password never appears in any
returned structure.

The score is the sum of five components totalling exactly 100: length (35),
character classes (25), diversity (20), predictable sequences (10) and known
breached patterns (10).

### Security Score - nothing is free

Each of the four checks is worth up to 25 points. A check you have **not run**
scores **zero** and is labelled "Not analyzed", so the score can never be
inflated by missing data. The report always states how many of the 100 points
were actually assessable.

## Measured results

Real numbers produced by the committed models, read from `models/metrics.json`
and displayed in the app's About page. These are measured on a held-out split,
not estimated.

### Phishing URL model

| Metric | Value |
| --- | --- |
| Algorithm | Random Forest, 400 trees, `balanced_subsample` |
| Training rows | 20,574 (majority class undersampled to 20,000) |
| Evaluation rows | 32,013 |
| Accuracy | 0.9982 |
| Macro F1 | 0.9227 |
| Phishing precision / recall / F1 | 0.9998 / 0.9984 / 0.9991 |
| Legitimate precision / recall / F1 | 0.7585 / 0.9573 / 0.8464 |

Accuracy looks excellent because the evaluation split mirrors the dataset's
99.5% phishing imbalance. **Macro F1 and the per-class figures are the honest
summary**, and the legitimate-class numbers are the ones that matter for a
user-facing tool.

## Known limitations

### The phishing training data is structurally biased

The supplied dataset contains **159,244 phishing URLs and only 820 legitimate
ones**. Critically, all 820 legitimate entries are bare apex domains with no
scheme and no path (`example.com`), while phishing entries are full URLs with
paths (`http://host/verify/account`).

The model therefore learns "has a path means phishing", and will report a very
high phishing probability for a perfectly legitimate URL that contains one -
for example `https://github.com/features`. Re-extracting the features
consistently, balancing the classes, and using balanced class weights all
improve the metrics but **cannot remove this bias**, because it is a property
of the data, not of the training procedure.

This is precisely why the architecture uses an aggregated, capped, rule-backed
decision instead of trusting the classifier alone. The limitation is disclosed
in the UI on the URL Scanner page, the Home page and the About page, and is
recorded in `models/metrics.json`.

**A dataset containing legitimate URLs with paths would remove this limitation.**
Until then, treat URL output as one signal among many.

### Other limits

- The password entropy figure is an approximation that ignores human
  password-selection bias. It is informational only.
- "Not in our weak-password list" does **not** mean a password has never
  leaked; only an online breach-database check can confirm that.
- QR decoding needs a reasonably sharp, high-contrast image.
- Spam recall of 0.87 means roughly 13% of spam is classified as ham.
- **No automated scanner can guarantee that anything is safe.**

## Privacy

- **Passwords** are analysed locally and never stored, logged, or transmitted.
- **Phishing and spam inference** runs entirely on your machine; no data leaves it.
- **Chat history** lives in the Streamlit session only and is never persisted.
- **Only VirusTotal lookups** (when you enable them) send a URL to a third party.
- **API keys** are read from environment variables, never stored in code or logged.

## Deploying to Render

1. Push the repository to GitHub, GitLab or Bitbucket.
2. In Render choose **New > Blueprint** and select the repository. `render.yaml`
   is picked up automatically.
3. The build runs `pip install -r requirements.txt` and the start command runs
   `streamlit run app.py`. Models are already committed, so nothing is trained.
4. Optionally add `GROQ_API_KEY` and/or `VIRUSTOTAL_API_KEY` under
   **Environment**. The app deploys and works without them.

The blueprint also sets a health check on `/_stcore/health`.

`opencv-python-headless` is used rather than `opencv-python` because the
headless wheel omits the GL libraries that containers lack; the full build
fails to import with `libGL.so.1` errors on Render.

> Free-tier instances sleep when idle, so the first request after a quiet
> period can take a few seconds.

## Troubleshooting

**"Phishing model unavailable" / "Spam model unavailable"**
The artifact is missing or corrupt. Rebuild it:

```bash
python training/train_phishing.py
python training/train_spam.py
```

**"Feature schema mismatch"**
`utils/url_features.py` changed after the model was trained. Retrain the
phishing model.

**The chatbot says the AI assistant is not configured**
No `GROQ_API_KEY` is set. The offline knowledge base is working as designed; add
the key to enable live answers.

**VirusTotal is not configured**
No `VIRUSTOTAL_API_KEY` is set. Local results are unaffected.

**`libGL.so.1: cannot open shared object file`**
The full `opencv-python` package got installed. Use
`opencv-python-headless`:

```bash
pip uninstall -y opencv-python
pip install opencv-python-headless
```

**The app starts on a different port**
Run `streamlit run app.py --server.port 8502`.
